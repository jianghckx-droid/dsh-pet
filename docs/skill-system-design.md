# 技能系统玩法设计

状态：早期玩法方案，保留共享反应与战斗风格方向；当前目标设计以 [技能系统完整机制设计](skill-system-complete-design.md) 为准。第一版原型与部分扩展动作已实现（2026-11），未实现项见 [技能系统架构设计](skill-architecture.md) 的实现落点。数值、槽位开放时机和具体平衡仍待试玩验证。

## 设计目标

宠物在侧栏中自动战斗，玩家通过阶段性的选择创造自己的 build。系统借鉴法术组合带来的创造感，但不要求玩家编写程序或理解复杂的指令顺序。

技能由简单组件组装而成，不同技能通过共享状态、敌人位置和触发时机产生配合。玩家应当能预测单个组件的大致作用，也能在战斗中发现超出单个组件的连锁效果。

一局的基本循环是：自动战斗 → 获得升级选择 → 获取或替换组件 → 观察技能变化 → 围绕新的敌群调整 build。

## 技能结构

```text
技能 = 动作 + 属性 + 修饰
```

动作决定技能如何接触目标，属性决定附带什么效果，修饰改变技能行为。动作单独存在时就是可用技能；属性和修饰槽可以为空。

例如，“飞弹 + 火焰 + 分裂”发射火焰飞弹，命中后向附近目标分裂；“光环 + 冰霜 + 扩大”在宠物周围形成范围更大的冰霜光环。

### 动作

| 动作 | 基础行为 | 主要作用 |
|---|---|---|
| 飞弹 | 朝敌人发射弹体 | 攻击远处目标 |
| 光环 | 周期性影响宠物附近的敌人 | 持续处理近身敌人 |
| 召唤 | 召唤自动攻击的伙伴 | 创造额外战斗单位 |
| 冲击 | 对指定区域产生一次范围效果 | 处理聚集的敌人 |

动作具有基础伤害、节奏和覆盖范围。同一属性装到不同动作上时，尽可能沿用相同规则：例如火焰飞弹命中时施加火焰效果，火焰光环生效时施加相同类型的效果。

### 属性

| 属性 | 基础效果 | 共享状态或资源 | 战斗倾向 |
|---|---|---|---|
| 火焰 | 命中造成伤害并施加灼烧 | 灼烧：短时间持续损失生命 | 持续输出 |
| 冰霜 | 命中造成伤害并施加寒冷 | 寒冷：降低移动速度 | 控场 |
| 雷电 | 命中造成伤害并施加充能 | 充能：可被后续雷电效果消耗 | 连锁、爆发 |
| 生命 | 伤害较低，并产生生命能量 | 宠物接触能量后回复少量生命 | 生存、续航 |

状态可以有层数上限和持续时间，但玩家不应需要记住复杂数字才能理解技能。生命能量应在合理时间内消失，避免战场堆积。

### 修饰

| 修饰 | 效果 | 取舍或用途 |
|---|---|---|
| 分裂 | 首次命中后向附近目标产生较弱的后续效果 | 将单体攻击扩展至多个目标 |
| 回响 | 一次技能效果结束后，延迟触发一次较弱效果 | 增加命中次数、加快状态积累 |
| 扩大 | 增加影响范围 | 覆盖更多敌人，但降低触发频率 |
| 聚焦 | 优先集中影响同一个目标 | 对付强敌，但减少额外目标数 |
| 牵引 | 命中时将敌人向效果中心拉近 | 聚怪，为范围效果创造机会 |
| 引爆 | 消耗目标已有的指定状态，造成额外效果 | 将积累转化为爆发，消耗原有状态 |

并非所有修饰都适用于所有动作。兼容性应遵循可理解的行为规则：例如扩大需要技能具有影响范围，分裂需要能产生独立投射物或攻击目标。选择界面应显示可装配的位置和原因。

引爆具体能消耗哪些状态、触发条件和收益需要在原型中明确；不应让玩家依赖未展示的隐藏配方。

## 技能之间的共享反应

反应是整个战场遵循的规则，不要求特定卡牌组合。不同技能可以共同施加状态、改变敌人位置，然后触发反应。

| 反应 | 条件 | 结果 |
|---|---|---|
| 传火 | 灼烧中的敌人被击败 | 一部分灼烧传给附近敌人 |
| 导电 | 带充能的敌人再次受到雷电效果 | 消耗充能，对附近敌人造成雷击 |
| 碎裂 | 寒冷达到条件的敌人受到强力命中 | 消耗寒冷，对附近敌人造成范围伤害 |

例如，冰霜牵引光环可以先将敌人减速、聚集；随后强力冲击触发碎裂。如果冲击同时施加火焰，被击败的敌人还可能向周围传火。

连锁要有清楚的终止条件。初版中，导电产生的雷击不再施加充能；碎裂产生的范围伤害不算新的强力命中。反应阈值、范围与数值由测试确定。

## build 示例

以下示例说明可能的玩法，而不是必须按固定配方收集的套装。各组合的最终兼容性以原型实现和测试为准。

- **野火流**：飞弹 + 火焰 + 分裂；光环 + 火焰 + 扩大。远处点燃多个目标，近处持续施加灼烧，通过传火处理密集敌群。孤立强敌附近没有其他敌人时，传火收益较低。
- **雷暴流**：飞弹 + 雷电 + 回响；召唤 + 雷电 + 分裂。多个攻击来源积累并消耗充能，频繁触发导电。敌人分散时连锁收益下降。
- **冰爆流**：光环 + 冰霜 + 牵引；冲击 + 任意属性 + 聚焦。先减速聚集，再用强力冲击触发碎裂。两次爆发之间存在空窗。
- **生命循环流**：召唤 + 生命 + 分裂，搭配影响宠物周围敌人的技能。召唤物攻击产生生命能量，宠物在战斗中吸收能量续航；输出偏低，需要应对被包围的风险。

## 一局中的成长

目标上限可设为最多三个技能，每个技能最多三个槽位；不要在开局一次性展示所有空槽。

1. 开局提供一个基础动作，让玩家先理解宠物的攻击。
2. 第一次升级提供属性选择，让玩家看到技能改变。
3. 后续开放修饰，改变技能行为。
4. 再开放第二个动作，让不同技能产生配合。
5. 随进程继续开放槽位或第三个技能。

升级时提供三选一，候选可以混合动作、属性和修饰。选择界面应显示装入后的完整描述，例如：“火球命中后分裂，点燃附近敌人。”有多个可装位置时让玩家选择；只有一个合理位置时可直接装入。

允许替换组件。可以先试验一个小型备用栏，保留试错空间，同时避免大量库存管理；备用栏大小和替换时机尚待验证。升级选择不应要求玩家在战斗中实时操作。

## 敌人设计方向

敌人通过行为、位置和数量制造不同问题，而不是要求玩家拥有唯一指定的解法。

| 敌人 | 行为 | 提出的问题 |
|---|---|---|
| 群游者 | 数量多、生命低，成群靠近 | 能否处理密集目标？ |
| 重甲兽 | 移动慢、生命高 | 能否集中输出或持续牵制？ |
| 游击者 | 保持距离并移动 | 能否覆盖远处和移动目标？ |
| 守护者 | 靠近其他敌人时提供防护 | 能否改变阵型或优先处理它？ |
| 分裂体 | 受击后分成多个弱小单位 | 能否应对突然增多的敌人？ |

每种敌人应允许多种应对方式。build 可以有明显的优势和弱点，但不应因为缺少某个指定组件而完全无法继续。

## 可读性与复杂度约束

- 一个组件只负责一类主要变化；同名状态尽量遵循同一套规则。
- 普通组合应能通过组件描述预测；特殊反应需有明确提示。
- 强力效果应有容易理解的代价，如扩大牺牲频率、聚焦牺牲覆盖、引爆消耗状态。
- 侧栏用颜色、动作和少量图标表达关键状态；详情面板展示技能伤害、反应触发次数等统计，帮助玩家理解结果。
- 战斗中的连锁必须有边界，并能在视觉上追溯主要因果。

## 第一版原型

先实现飞弹、光环、冲击三个动作；火焰、冰霜、雷电三个属性；分裂、回响、扩大、牵引四个修饰；传火、导电、碎裂三个共享反应。最多装备两个技能，敌人先使用群游者、重甲兽和游击者。

原型主要验证：玩家能否预测组合效果；能否主动创造至少两种明显不同的打法；能否看懂连锁发生的原因。通过验证后，再考虑召唤、生命属性、更多修饰和第三个技能。
