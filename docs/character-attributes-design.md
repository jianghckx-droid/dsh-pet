# 角色属性系统设计

> 状态：已落地（v1）；换算、升级频率与数值仍需通过真实试玩继续校准。
> 本文描述已实现的行为；实现状态与取舍见文末「实现状态」。

## 目标与分工

借鉴《暗黑破坏神 IV》的基础属性与装备词条思路，为自动战斗提供可预测的成长和构筑选择。角色升级提供可自由分配的基础属性点；装备提供护甲、通用伤害、攻击速度、暴击率、暴击伤害及条件伤害等战斗属性。基础属性通过固定换算影响部分战斗属性，装备词条则直接增加战斗属性。

火焰、冰霜、雷电仍是技能元素组件，须与角色基础属性区分。装备的槽位、获取、替换和词条生成规则留待装备系统设计。

## 基础属性与升级

| 基础属性 | 每投入 1 点的效果 | 定位 |
|---|---|---|
| 力量 | 护甲 +2 | 稳定减伤 |
| 敏捷 | 攻击速度 +1%，暴击率 +0.5 个百分点 | 攻击频率与暴击 |
| 智力 | 通用伤害加成 +2% | 所有技能与反应的输出 |
| 体魄 | 最大生命 +1 | 承受伤害 |

四项基础属性初始均为 0；每次角色升级获得 1 个属性点，可自由投入任一基础属性，不随机抽取候选。所有战斗风格使用同一换算，避免风格切换改变属性点的含义。属性点一经分配是否可以重置，留待后续决定。

升级界面同时展示四个属性、各自点数及投入后的实际变化，玩家自行选择；例如“力量 3 → 4，护甲 6 → 8”。面板里的属性栏默认折叠成一行（标题 + 可用点数 + 护甲 / 暴击摘要），点标题展开四项属性与加点按钮，避免占用战场高度；加点后保持展开，再次点击收起。最大生命提升时，当前生命同步增加相同数值。

技能组件成长仍按现有机制进行：首次组件选择提供元素，之后按现有节点提供动作、元素或修饰。属性点不与组件候选竞争；同一次升级触发两者时分别完成。具体节点及界面衔接实施前核对现有机制。

## 战斗属性与来源

| 战斗属性 | 基础值 | 属性点换算 | 装备可提供 |
|---|---:|---|---|
| 最大生命 | 24 | 体魄 | 可在装备设计时决定 |
| 护甲 | 0 | 力量 | 是 |
| 通用伤害加成 | 0% | 智力 | 是 |
| 攻击速度 | 0% | 敏捷 | 是 |
| 暴击率 | 5% | 敏捷 | 是 |
| 暴击伤害 | 50% | 无 | 是 |
| 条件伤害加成 | 0% | 无 | 是 |

同一战斗属性的基础值、属性点换算和装备词条相加后，再应用对应上限与结算公式。未装备物品时仍保留表中的基础值及属性点收益。条件伤害包括火焰伤害、对寒冷敌人伤害等，留给后续装备系统。

## 伤害结算

```text
最终伤害 = 基础伤害
         × (1 + 通用伤害加成 + 满足条件的伤害加成之和)
         × 暴击倍率
```

普通命中的暴击倍率为 1；暴击命中为 `1 + 暴击伤害`，初始为 1.5。条件伤害在满足条件时与通用伤害相加；同一伤害可满足多个条件，每条词条只计算一次。

例如基础伤害为 2，智力提供通用伤害加成 12%，装备提供火焰伤害加成 15%，火焰飞弹暴击造成 `2 × (1 + 0.12 + 0.15) × 1.5 = 3.81`。内部保留小数，界面显示时再处理精度，避免小幅成长因每次命中取整而失效。

| 伤害来源 | 通用伤害 | 符合条件的加成 | 暴击 |
|---|---|---|---|
| 技能直接命中 | 是 | 是 | 是 |
| 灼烧持续伤害 | 是 | 是 | 否 |
| 导电、碎裂等反应 | 是 | 是 | 否 |
| 分裂、回响 | 是 | 根据自身伤害标签 | 是 |

分裂和回响从未应用角色属性的基础伤害出发，分别结算属性，避免重复加成。每个独立命中单独判定暴击，使用现有显式 RNG，确保相同种子和输入仍可复现。

## 防御与施放频率

```text
护甲减伤 = min(60%, 护甲 / (护甲 + 100))
受到伤害 = 原始伤害 × (1 - 护甲减伤)
实际冷却 = 基础冷却 / (1 + 攻击速度)
```

- 护甲对当前所有敌人伤害统一生效，减伤上限 60%。
- 攻击速度上限 100%，作用于技能施放冷却，不改变灼烧跳伤间隔或飞剑接触间隔等实体内部计时。
- 暴击率上限 100%。

## 存档与成长周期

阵亡重试保留本轮已分配和未分配的属性点；通关后按现有规则重开并重置本轮成长。切换战斗风格同样按新风格重开本轮，属性点一并重置。

没有属性字段的旧存档按「已投入 0 点、每升一级 +1」推算未分配点数：旧档从未花过点，因此 `等级 - 1` 是可准确推算的，不属于凭空补发。属性点一旦投入本轮不可撤回。

## 接入与验证

- 公共伤害入口 `resolve.js` 的 `executeHit` / `executeStatusDamage` 统一调用 `attributes.js` 的 `resolveDamage`，各动作不重复实现加成。
- 每条伤害命令标注通道：`direct`（动作直接命中）、`derived`（分裂 / 回响 / 引爆）、`dot`（灼烧跳伤）、`reaction`（导电、碎裂），元素标签继续来自技能内容。
- 施放冷却在 `runtime.js` 统一按攻击速度折算；实体内部计时不变。
- 属性在命中结算时读取当时的战斗属性；飞行中的实体与延迟命令不做额外快照，加点立即生效。
- 数值验证：`test/attributes.test.mjs` 覆盖换算、上限、文档示例 3.81、通道暴击规则、固定种子复现、加点与存档；`npm run arena` 复跑 15 层，加入暴击后 15 层通关率方向不变。

后续校准：固定种子复现、低伤害下的小数结算、加成不重复、各来源暴击规则、属性点自由分配与存档已由测试覆盖；15 层通关率、45 秒超时率、不同加点路线的收益，以及未来装备叠加后的收益，仍需用 `npm run arena` 与真实试玩继续校准，再据此调整升级频率和换算数值。

| 测试 | [`test/attributes.test.mjs`](../test/attributes.test.mjs) | 换算、上限、文档示例、条件伤害不重复、通道暴击规则、固定种子、加点 / 存档 / 预览；折叠展开与点击加点在 `test/client.test.mjs` |

已知取舍：

- **条件伤害只有接入点**：`bonuses.conditional` 支持按元素、标签、目标状态匹配，每条规则只算一次；装备系统落地前没有稳定来源，只由测试构造。
- **加成在结算时读取**：飞行中的弹体与延迟回响使用命中瞬间的战斗属性，而不是施放瞬间的快照。这样加点即时生效，也让"同一发弹体在飞行中升级"结果可解释。
- **暴击率基础 5%**：相当于整体输出 +2.5%；对 15 层通关率的方向没有改变，但暴击的表现成本（额外碎片）需要真实设备复核。
- **独立 RNG 流**：加入暴击后，已有 seed 的刷怪位置与三选一候选完全不变，便于对照旧报告。
- **升级频率未调整**：仍是"每级 1 点、每两级一次技能三选一"；若加点收益压过构筑选择，再考虑提高技能三选一频率而不是砍属性。
