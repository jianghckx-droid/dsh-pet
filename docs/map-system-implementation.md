# 99 层随机地图系统：实现说明

> 实现说明 v1 · 2026-11-12。对应设计提案 [map-system-design.md](map-system-design.md) 与
> [map-generation-design.md](map-generation-design.md)；本文记录**已经落地**的行为、参数与验证方式。
> 玩法数值仍是原型参数，需要试玩校准。

## 1. 实现范围

| 模块 | 文件 | 内容 |
|---|---|---|
| 随机数 | `src/game/map/rng.js` | FNV-1a 种子派生 + mulberry32 序列，显式种子，不使用 `Math.random()` |
| 配置 | `src/game/map/config.js` | 地点类型、自动偏好、99 层与 11 层原型配置、权重与保底间隔 |
| 结构 | `src/game/map/topology.js` | 分层有向图：节点数量、列位置、比例映射连线、覆盖补边 |
| 类型 | `src/game/map/types.js` | 固定层 → 锚点层 → 权重抽取 → 精英上限 → 迭代修正 |
| 验证 | `src/game/map/validate.js` | 结构、可达性、固定层、逐路线保底（状态集合传播） |
| 内容 | `src/game/map/content.js` | 战斗构成、事件选项、商店货架、金币奖励、节点摘要 |
| 生成 | `src/game/map/generate.js` | 尝试 → 修正 → 验证 → 确定性保底模板 |
| 进度 | `src/game/map/run.js` | 本局状态、节点进入 / 结算、休息 / 事件 / 商店、自动路线、存档 |

界面在 `client.js`（地图栏、下一站按钮、节点面板、自动模式），战斗接入在
`floors.js`（深层构成）与 `arena.js`（节点战斗构成与跨节点生命）。

## 2. 数据模型

```js
// 节点（生成后即固定，存档原样保存）
{
  id: "12-2",
  floor: 12,
  column: 2,
  type: "event",          // normal | elite | rest | event | shop | boss
  next: ["13-1", "13-2"],
  content: {},            // 已生成内容：金币 / 敌人提示 / 事件选项 / 商品
}

// 本局地图状态（存档里的 map 字段）
{
  mapVersion: 1,
  seed: 482719,
  depth: 99,
  config: { /* 生成参数快照 */ },
  nodes: [],
  startId: "1-0",
  bossId: "99-0",
  currentNodeId: "12-2",
  visited: ["1-0", "2-1"],
  nodeStates: { "12-2": { status: "active", purchases: [1] } },
  gold: 124,
  life: 18,
  lifeMax: 26,
  autoMode: "balanced",
  failures: 0,
  finished: false,
}
```

- 节点状态：`active`（进行中）→ `done`（已结算）。奖励只在 `done` 那次发放，重复结算返回 `alreadyDone`。
- `visited` 记录走过的路线，界面据此保留痕迹。
- `nodeStates[id].purchases` 记录商店已买商品，读档不会重复购买。

## 3. 生成算法

### 3.1 种子与随机流

- 主种子 → `hash(seed, "attempt", n, version, depth)` 派生每次尝试。
- 同一次尝试再派生 `topology` / `node-types` / `anchors` 三条独立流。
- 节点内容种子是 `hash(主种子, 节点 ID, "content")`：**与尝试次数无关**，所以玩家路线、商店次数、
  战斗随机数都不会改变其他节点已固定的内容。
- 哈希与 RNG 算法属于存档兼容范围：改动必须同时提升 `MAP_VERSION`。

### 3.2 结构

- 第 1 层 1 个节点（普通战斗）；第 2–97 层每层 3–5 个节点；第 98 层 1 个休息点；第 99 层 1 个 Boss。
- 层宽有 70% 概率沿用上一层，避免锯齿状宽度抖动。
- 连线：源节点先接到比例位置对应的目标，45% 概率再连一个相邻目标形成分叉；
  随后给任何没有入边的目标补一条最近源的边，保证没有孤立节点。
- 构造即保证：每个非 Boss 节点至少一条出边，每个非起点节点至少一条入边。

### 3.3 类型：锚点 + 权重 + 修正

随机权重满足不了「任意连续 12 层至少一个休息点」这类**逐路线**约束：
12% 休息权重下，一条 12 层路线约有 22% 概率完全没有休息点；靠事后修补会把
休息点挤成连续的整排。因此实现分成三层：

1. **锚点层**：休息与商店改为整排同类型，层间距在区间内抖动（休息 7–10 层，商店 8–11 层），
   任何路线每层必经过一个节点，所以只要锚点间距不超过保底间隔，逐路线约束必然成立。
   两种锚点之间保留至少 2 层间隔。
2. **权重抽取**：非锚点层只抽普通 / 精英 / 事件（权重 45 / 13 / 20）。
3. **修正**：按逐路线状态检查结果迭代修正——休息间隔超限 → 该节点改休息，商店超限 → 改商店，
   连续精英 / 前 3 层精英 → 改普通，整层全精英 → 末列改事件，单层精英超过 2 个 → 多余的改普通。
   修正只做「更安全」的方向，且不改写固定层。

### 3.4 验证

`validateMap` 检查：

- ID 唯一、层数与列号合法、连线只指向下一层且不重复、不指向不存在的节点。
- 固定层：第 1 层普通、第 98 层休息、第 99 层 Boss。
- 每个节点从起点可达、都能通往 Boss；非 Boss 节点没有死路。
- 前 3 层无精英；同层不全精英；单层精英 ≤ 2。
- **逐路线保底**：按层传播每个节点的状态集合（距上次休息 / 商店的层数、上一节点是否精英），
  同 `prevElite` 下按 Pareto 支配剪枝，只丢被完全支配的状态，因此不会漏判某条路线。

### 3.5 保底模板

超过 `attempts`（24）仍不通过时使用确定性模板：每隔 `restGap-2` 层整排休息、
每隔 `shopGap-3` 层整排商店，两者同时到期时交替放置；模板同样跑完整验证。
极端配置（例如休息与商店间隔同为 2 层）无法同时满足时返回 `valid: false` 与可诊断错误，
不会无限重试。

## 4. 与战斗的衔接

- 节点类型给出战斗构成：`nodeBattlePlan(node)` 返回 `{ def, modifier }`。
  普通节点 `modifier = null`，精英节点 `modifier = "elite"`（数量减少、末位敌人强化、清层补一次三选一），
  Boss 节点 `modifier = "boss"`（8 只敌人 + 末位 Boss ×3.4 生命、+2 伤害、击败补两次三选一）。
- `createBattle({ plan, life })` 接受地图给出的构成与**跨节点生命**：战斗从 `run.life` 开始，
  胜利后剩余生命写回地图。
- 深层（16–99 层）不再逐层手写：`deepFloorPlan` 从第 15 层的数量与混合平滑延伸，数量 16 只封顶；
  敌人生命成长在 15 层后改为更缓的曲线（0.045/层）、伤害在第 30 / 55 / 80 层各 +1，
  避免 99 层变成纯数值墙。

## 5. 进度与自动路线

状态机：`fight`（战斗中）→ `result`（结算）→ `map`（选下一站）或 `node`（休息 / 事件 / 商店面板）→ `fight`。

- 只能进入当前节点 `next` 列表里、且状态为 `unvisited` 的节点；当前节点未结算时不可选下一站。
- 战斗失败：保留当前节点与构筑，补一次三选一，生命回满后重试；节点奖励不重复发放。
  连续失败 3 次时暂停自动重试并显示原因，玩家调整构筑后点「重试当前节点」继续，
  避免后台无限重复开打。
- 休息点：恢复 30% 最大生命或获得一次三选一；满血时治疗置灰，仍可强化或安全离开。
- 事件点：选项写出代价与结果，金币 / 生命不足时置灰；事件不会把生命扣到 0 以下。
- 商店：商品可看可买，同件只能买一次，买完可以离开。

自动路线（`稳健 / 均衡 / 冒险`）评分考虑节点类型、生命比例、金币与**未来 3 层**的连线，
而不是只看眼前一个节点：

| 模式 | 偏向 |
|---|---|
| 稳健 | 低生命大幅加权休息点，精英固定重罚 |
| 均衡 | 生命低于 45% 时避开精英，金币充足时偏向商店 |
| 冒险 | 精英优先，满血时压低休息点权重 |

自动暂停条件：生命 ≤ 20% 且可选节点没有休息点；生命 < 35% 且可选节点全是精英；
非战斗节点里事件没有任何「无代价」选项。暂停时保留自动模式并显示原因，玩家随时可手动接管。

## 6. 存档

- 存档版本升到 **7**，新增 `map` 字段（完整节点、路线、商店售出、金币与生命）。
- 只保存种子不够：算法或权重更新后同一颗种子会产生不同地图，所以节点与内容一起保存。
- 一份 99 层地图存档约 100 KB（390 个节点 × 连线 × 内容），三个槽位仍在 localStorage 预算内。
- `mapVersion` 不符、节点缺失、当前节点指针失效时，读档会按存档记录的层数**重新生成**一张地图并提示，
  而不是让整份存档失效。
- v5 / v4 / v3 旧存档同样走这条迁移路径：构筑、等级、累计战绩保留，地图按所在层补齐。

## 7. 界面

- 地图栏默认折叠成一行：当前进度、当前节点与下一站；展开后是按层排列的节点方块，
  可选节点是绿色实心按钮，当前节点高亮，已走节点保留描边，未到达节点淡化。
- 节点使用「图标 + 文字」而不是只靠颜色区分；点击任意节点显示类型说明与内容摘要。
- 分叉时画布上方出现「下一站」按钮；自动路线暂停时同一位置显示暂停原因。
- 休息 / 事件 / 商店在画布上以面板呈现，代价、结果与置灰原因都直接写在选项里。
- 自动模式（手动 / 稳健 / 均衡 / 冒险）在地图展开后切换，随时可接管。

## 9. 已知限制与待定事项

- 99 层还没有分段、主题与内容池：整张图共用一套敌人与事件，深层只靠数量 / 数值成长。
- 永久成长（跨局解锁）未接入，只有风格解锁沿用旧的「最高层数」条件。
- 事件没有「安全选项」标记字段，自动路线用「无代价」近似判断；需要设计确认更明确的标记。
- 金币与生命数值只做了粗略校准：单场战斗金币随层数线性增长，商店价格同向增长，
  但还没有模拟整局供需。
- 工作信号（token 压力 / 过载潮）仍然只作用于当前战斗，与地图推进的关系待设计。
- 地图相似度只按「每层类型签名」粗测；结构相似度与高难度分段留待后续。
