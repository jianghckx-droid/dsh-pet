# 随机地图生成方案

> 讨论稿 v0.1 · 2026-11-12。本文是实现建议，具体算法与参数需通过原型验证。玩法规则见 [地图系统设计](map-system-design.md)。

## 1. 目标

每次新游戏使用一个主种子生成 99 层地图。同版本生成器、配置和内容池使用相同种子时，得到相同结果；不同种子产生不同的路线和遭遇。种子可用于复现、分享与排查问题。

地图是分层有向图：节点代表地点，边代表通往下一层的道路。玩家只能沿连线前进。第 1 层为普通战斗，第 98 层为休息点，第 99 层为最终 Boss。99 层分段与区域内容池暂不设计。

## 2. 随机数与种子

使用可显式设置种子的确定性伪随机数生成器，不使用 `Math.random()` 生成地图。同一算法、种子和调用顺序应产生相同序列。实现前检查并优先复用项目现有显式 RNG；固定随机数算法、种子哈希、节点遍历顺序与生成配置。

从主种子派生互相独立的随机流：

| 用途 | 决定内容 |
|---|---|
| 地图结构 | 节点数量、位置与连线 |
| 节点类型 | 普通战斗、精英、事件、商店、休息的分布 |
| 节点内容 | 具体敌人、事件、商店商品 |
| 战斗 | 战斗中需要随机的行为和结果 |

具体节点的内容种子可由 `hash(主种子, 节点 ID, 用途)` 派生，例如事件使用 `hash(seed, nodeId, "event")`。这样玩家走过的路线、商店操作次数或战斗中的随机数调用，不会改变其他节点的内容。哈希编码方式和版本也必须固定。

## 3. 数据结构

示意结构如下，字段和序列化格式待实现时确定：

```js
{
  id: "12-2",        // 稳定且唯一的节点 ID
  floor: 12,
  column: 2,
  type: "event",
  next: ["13-1", "13-2"],
  content: {},       // 已生成或已揭晓的内容
  state: {}          // 完成、选择和奖励领取状态
}
```

每条边只指向下一层的相邻位置。节点允许分叉和汇合，但不能横向移动或跳层。

## 4. 生成流程

1. **创建节点**：创建第 1 层起点；第 2–97 层初步各生成 3–5 个节点；第 98、99 层分别创建休息点和最终 Boss。
2. **生成路线**：从起点生成若干条通向终点的完整路径，相邻层只连接相邻位置，允许分叉和汇合。
3. **修正结构**：补充必要连线或移除未接入完整路线的节点，确保每个保留节点既从起点可达，也能通往终点。
4. **分配类型**：按权重分配地点类型，再应用保底和限制规则。初始权重见地图系统设计；权重和间隔均为待验证参数。
5. **填充内容**：通过节点独立种子确定具体敌人、事件和商品。分段设计完成前先使用基础内容池。
6. **验证结果**：检查图结构和所有有效路线的约束。不通过时进行确定性修正或使用确定性的重试种子重新生成。

### 结构与路线约束

- 前 3 层不出现精英；任意有效路线不得连续经过两个精英。
- 每条有效路线的任意连续 12 层至少有一个休息点，任意连续 18 层至少有一个商店。
- 保留非精英路线；同一层不应所有可选节点都是精英。
- 每个节点从起点可达且有路径通往终点；不允许死路、跳层或指向不存在节点的连线。
- 第 1、98、99 层满足固定类型要求。

这些间隔是初始建议。验证要覆盖**每条有效路线**，不能只检查每层是否存在相应节点。可以逐层传播「距离上一次休息点 / 商店经过的层数」及「上一节点是否精英」等状态，任何路径违反限制即视为验证失败；实现时应注意分别保留可能导致违规的状态，不能只保留某个节点的一条最优历史。

### 生成伪代码

```js
function generateMap(seed, config) {
  for (let attempt = 0; attempt < config.maxAttempts; attempt++) {
    const attemptSeed = hash(seed, "attempt", attempt)
    const topologyRng = createRng(hash(attemptSeed, "topology"))
    const typeRng = createRng(hash(attemptSeed, "node-types"))

    const nodes = createNodes(topologyRng, config)
    connectPaths(nodes, topologyRng, config)
    assignNodeTypes(nodes, typeRng, config)

    if (validateMap(nodes, config)) return nodes
  }
  return generateValidatedFallback(seed, config)
}
```

伪代码省略了内容生成和结构修正。重试必须有上限；超限后使用同样经过验证的保底模板，或返回可诊断的错误，不能无限重试。保底路径也需保持确定性。

## 5. 存档与版本

不要只保存种子：算法、权重或内容池更新后，同一个种子可能产生不同地图。建议同时保存：

```js
{
  mapVersion: 1,
  seed: 482719,
  nodes: [],
  currentNodeId: "12-2",
  visitedNodeIds: [],
  nodeStates: {}
}
```

- `mapVersion` 标识生成规则版本，供旧存档兼容或迁移。
- `seed` 用于复现、分享和排查。
- `nodes` 保存生成后的节点、连线与需要固定的内容，确保更新后仍能继续当前冒险。
- `currentNodeId`、`visitedNodeIds` 和 `nodeStates` 保存进度、事件选择、商店售出与奖励领取等状态，避免读档重复获取。

具体内容可预生成，也可按节点种子延迟生成；已揭晓或发生变化的内容必须保存实际状态。分享种子时应同时标明生成器版本及影响结果的配置或内容版本；仅相同种子不足以跨版本保证相同地图。

## 6. 验证与原型

先实现 11 层原型：第 1 层普通战斗、第 10 层休息、第 11 层测试 Boss，中间接入其他节点。验证通过后再扩展至 99 层。

1. 相同种子、版本和配置产生完全一致的地图；不同种子具有足够差异。
2. 批量生成种子，检查所有节点可达、可通向终点，且所有有效路线满足约束。
3. 验证存档往返：地图、当前位置、事件、商店与奖励领取状态一致。
4. 改变战斗随机数调用或玩家路线，不改变其他节点已固定的内容。
5. 测量生成耗时、重试次数、保底模板使用率及地图相似度，确认约束没有使地图过于固定。
6. 测试极端和非法配置，确认生成失败时可诊断且不会无限循环。
