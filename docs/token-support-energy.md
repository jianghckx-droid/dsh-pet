# Token 支援能量设计

> 设计提案，尚未实现 ｜2026-11-08

## 目标

让玩家的工作为宠物提供可见的帮助。token 不再直接增加战斗压力；关卡自身的敌人、锁和精英继续提供挑战。支援应当有用，但不让消耗更多 token 成为通关的必要条件。

## 核心规则

以下比例和效果是首版建议，需通过试玩调整。

- 使用当前工作区各会话的 **output token 增量**计量：每 500 token 获得 1 格支援能量，不足 500 的部分保留到下一次。
- 每积累 3 格能量，在战斗中自动释放一次支援技能。首版建议使用短暂护盾；护盾数值、持续时间和触发条件待平衡测试确定。
- 能量和未满一格的进度可跨层保留；储存格数设上限，避免大量输出导致战斗收益失控。具体上限待测试确定。
- 满能量时不再继续储存，界面显示“能量已充满”；技能消耗能量后可以继续积累。
- 移除每 500 token 追加敌人及每 3000 token 强制触发过载潮的规则。普通刷怪和关卡难度不受 token 数量影响。

## 玩家反馈

- HUD 显示当前能量、上限及下一格的积累进度；自动释放时用简短文字和特效展示护盾生效。
- 区分计量口径：支援能量来自 output token，现有累计消耗显示的是包含输入的总 token，界面应分别标明，避免让玩家误以为二者比例不一致是故障。
- 支援效果无需玩家操作，不应遮挡战斗或频繁打断工作。

## 边界与待验证事项

- 沿用现有会话首次发现时记录基线的行为，不把历史 token 一次性兑换成能量。
- 非战斗阶段可以积累能量，进入战斗后再自动释放；跨层、失败重试和重新打开面板时的保存范围需要在实现前明确。
- 评估护盾触发条件、储存上限和高输出场景下的释放频率，确保支援有感但不会覆盖 build 和关卡机制。
- 可在后续探索累计能量解锁清层后三选一；这不是首版规则，也不要求玩家先面对额外怪潮。
